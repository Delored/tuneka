# Windows x64 native artifacts

Run the following from `rust/` in PowerShell 7 on Windows x64 with Visual Studio 2022 C++ build tools, a Windows SDK containing `fxc.exe`, x64 LLVM (`libclang.dll`), Python 3 and the repository's pinned Rust toolchain installed:

```powershell
./packaging/windows/build.ps1 -VcpkgRoot C:/tuneka-build/vcpkg -OutputDirectory dist/windows-x64
```

`VcpkgRoot` must be a dedicated build directory without spaces. The script initializes the x64 Visual Studio developer environment using `vswhere.exe` and `Launch-VsDevShell.ps1`, selects the SDK's `fxc.exe` explicitly for GPUI release HLSL shader compilation, and uses `LIBCLANG_PATH` or `C:/Program Files/LLVM/bin` for FFmpeg bindgen. It does not run an interactive installer or modify a global vcpkg checkout. The `runtime_shaders` Cargo feature only changes the macOS path; Windows release GPUI still needs the SDK shader compiler. GUI execution uses Windows Direct3D, DirectWrite and normal OS libraries.

The native registry and vcpkg checkout are pinned to [2025.07.25 / dd3097e305afa53f7b4312371f62058d2e665320](https://github.com/microsoft/vcpkg/tree/dd3097e305afa53f7b4312371f62058d2e665320). That registry contains [FFmpeg 7.1.1, port revision 3](https://github.com/microsoft/vcpkg/blob/dd3097e305afa53f7b4312371f62058d2e665320/ports/ffmpeg/vcpkg.json), compatible with the locked `ffmpeg-next` 8 / `ffmpeg-sys-next` bindings and the project's tested FFmpeg 7 API. Source archives and build tools have checksums in the pinned port/tool definitions. Explicit features select every library enabled by `ffmpeg-next` defaults, plus LAME MP3 encoding, Opus, dav1d AV1 decoding, libvpx VP8/VP9, x264 H.264 encoding and zlib for PNG covers. H.264/VP8 encoders are required by the workspace's real-media tests. Native AAC/FLAC/PCM support comes from FFmpeg. The `x264`/`gpl` selection makes this FFmpeg build GPL; native licenses are copied from the actual install. No `all`, nonfree feature, FFmpeg executable or ffprobe executable is selected.

The shared `x64-windows` triplet matches the dynamic MSVC CRT. `VCPKG_ROOT/installed` is used deliberately: the locked Rust `vcpkg` helper searches that layout. `VCPKGRS_TRIPLET=x64-windows` and `VCPKGRS_DYNAMIC=1` select these shared libraries. `VCPKG_DOWNLOADS` may point to a workflow source-download cache. `VCPKG_DEFAULT_BINARY_CACHE`, when explicitly supplied, enables a local source-build binary cache; inherited external binary feeds are disabled. Cache keys should include the manifest and build-script hash. A native cold build can take considerably longer than the Rust build.

The build runs locked release build/tests across the workspace, including FFmpeg output and MCP subprocess protocol tests, before packaging. The output directory contains `Tuneka-VERSION-windows-x64.zip` and its SHA-256 checksum. The ZIP includes CLI/TUI/MCP/GPUI executables, native release DLLs, the selected toolset's app-local MSVC runtime, license inventory, exact native package versions, dependency import map, build metadata and runtime smoke evidence. Every EXE/DLL is checked for x64 PE architecture and its recursive import closure is checked against adjacent DLLs or named Windows OS components. Unknown missing imports fail the build. Windows API-set DLL contracts are supplied by the OS. The smoke launches packaged CLI and MCP with only Windows directories on `PATH` and isolated state/output directories; MCP initialization, all nine tool schemas, empty job listing and EOF shutdown are exercised without a network request.

The ZIP is an unsigned development CI artifact. The script does not claim clean consumer-system installation, GUI/TUI interaction, live YouTube download or physical GPU coverage. Windows 10/11 x64 and a compatible Direct3D driver are the desktop baseline; Windows N may require Microsoft's Media Feature Pack. Windows ARM64 remains deferred in the implementation plan. Public redistribution still requires complete corresponding-source and license obligations, including the [MSVC runtime terms](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files). No release is published by these scripts.
